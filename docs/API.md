# API Reference & Conventions

The **OpenAPI 3 schema** generated by drf-spectacular is the authoritative contract for REST:

- Schema: `GET /api/schema/` (YAML/JSON)
- Swagger UI: `/api/docs/` (development, and staff only in production)

This document covers the conventions behind that schema, the endpoint map, and the **WebSocket protocol**, which OpenAPI does not describe.

---

## 1. REST conventions

### Base URL & versioning

- All endpoints live under `/api/v1/`. A breaking change means `/api/v2/`. Additive changes stay in v1.
- JSON only (`Content-Type: application/json`). File bytes never go through the API (see Media).

### Authentication

- Cookie-based JWT (`access`, `refresh`). Clients never handle tokens directly.
- Unsafe methods (`POST`, `PUT`, `PATCH`, `DELETE`) must send the `X-CSRFToken` header, matching the `csrftoken` cookie.
- `401` with `code: "token_not_valid"` means the client should call `POST /auth/refresh` once, then retry.

### Resource naming

- Plural nouns, nested at most one level: `/servers/{id}/channels`, `/channels/{id}/messages`.
- IDs are UUID strings.
- Actions that aren't CRUD use sub-resources: `POST /servers/{id}/members/{user_id}/kick`.

### Pagination

- **Cursor pagination** for messages, notifications and audit logs:
  - `GET /channels/{id}/messages?limit=50` → newest first
  - `?before=<message_id>` (older history) or `?after=<message_id>` (backfill after reconnect)
  - Response: `{ "results": [...], "next": "<cursor|null>", "previous": "<cursor|null>" }`
- **Page-number pagination** (`?page=&page_size=`, max 100) for small, stable lists (discovery, members).

### Filtering, search, ordering

- `django-filter` query params, for example `?topic=gaming&q=python`.
- Message search: `GET /servers/{id}/messages/search?q=...&author=&channel=&has=attachment&before=&after=`.

### Errors

Every error has the same shape:

```json
{
  "type": "validation_error",          // validation_error | authentication_error | permission_denied | not_found | throttled | conflict | server_error
  "code": "invalid",                   // machine-readable
  "detail": "Human-readable summary.",
  "fields": { "email": ["Enter a valid email address."] },   // only for validation_error
  "request_id": "01J…"
}
```

| Status | Meaning |
|---|---|
| 400 | Validation error |
| 401 | Not authenticated / token expired |
| 403 | Authenticated but lacks permission (for a resource the user can see) |
| 404 | Not found, **or not visible to the user** (avoids leaking existence) |
| 409 | Conflict (duplicate nonce, already a member, …) |
| 429 | Throttled (`Retry-After` header included) |

### Idempotency

`POST /…/messages` accepts a client-generated `nonce`. A repeat of the same `(author, nonce)` returns the original message with `200` instead of creating a duplicate.

### Rate limits (initial values)

| Scope | Limit |
|---|---|
| `auth_login` | 5/min per IP + 10/hour per email |
| `auth_register`, `password_reset` | 5/hour per IP |
| `message_send` | 10 per 10 s per user (plus channel slow mode) |
| `media_sign` | 30/min per user |
| `invite_create` | 20/hour per user |
| `user` default | 120/min |
| `anon` default | 30/min |

## 3. WebSocket protocol

### Endpoint & auth

- URL: `wss://<host>/ws/` (`ws://localhost/ws/` in development).
- Auth: the access cookie is sent automatically with the handshake. `Origin` must match `ALLOWED_HOSTS`.
- One connection per browser tab. All subscriptions are multiplexed over it.

### Frame format

Every frame is a JSON object:

```json
{ "op": "event", "type": "message.created", "data": { … }, "seq": 1042 }
```

| Field | Description |
|---|---|
| `op` | `event` (server→client push), `request` (client→server), `response` (server reply to a request), `error` |
| `type` | Event or request name (`resource.verb`) |
| `id` | Client-chosen correlation ID on `request`, echoed on the `response` |
| `data` | Payload. Resource payloads use **the same serializers as REST** |
| `seq` | Per-connection increasing sequence number, used for debugging and gap detection |

### Client → server requests

| type | data | Notes |
|---|---|---|
| `subscribe` | `{server_id?, channel_id?, dm_id?}` | Replaces the current view subscription. Permission-checked |
| `unsubscribe` | `{channel_id? …}` | |
| `typing.start` | `{channel_id \| dm_id}` | Throttled to 1 per 3 s on the client, and rate-limited on the server |
| `presence.heartbeat` | `{}` | Every 30 s |
| `presence.set` | `{status}` | `online`/`idle`/`dnd`/`invisible` |
| `reauth` | `{}` | Re-reads the refreshed access cookie. Sent after a REST refresh |

> Messages are **not** sent over the WebSocket. They are sent with `POST /messages` (ADR-007).

### Server → client events

| type | Group | data |
|---|---|---|
| `ready` | — | `{user, session_id, heartbeat_interval}`, sent right after connect |
| `message.created` | channel / dm | Message (with `nonce` for the author's reconciliation) |
| `message.updated` | channel / dm | Message |
| `message.deleted` | channel / dm | `{id, channel_id \| dm_id}` |
| `reaction.added` / `reaction.removed` | channel / dm | `{message_id, emoji, user_id, count}` |
| `typing.started` | channel / dm | `{user_id, channel_id \| dm_id, expires_in: 8}` |
| `poll.updated` | channel / dm | `{poll_id, options: [{id, votes}], total, closed_at}` |
| `channel.created` / `channel.updated` / `channel.deleted` | server | Channel |
| `category.*` | server | Category |
| `server.updated` / `server.deleted` | server | Server |
| `member.joined` / `member.updated` / `member.left` | server | Member |
| `role.created` / `role.updated` / `role.deleted` | server | Role |
| `presence.updated` | server | `{user_id, status}` |
| `notification.created` | user | Notification |
| `read_state.updated` | user | `{channel_id \| dm_id, last_read_message_id, mention_count}` (syncs across tabs) |
| `dm.created` / `dm.updated` | user | DMConversation |
| `server.joined` / `server.removed` | user | Server (sent when you are added, kicked or banned) |
| `export.ready` / `export.failed` | user | `{export_id}` |

### Close codes

| Code | Meaning | Client action |
|---|---|---|
| 1000 | Normal close | — |
| 1001 / 1006 | Server restart / network drop | Reconnect with backoff (1 s → 30 s max, with jitter), then backfill |
| 4400 | Malformed frame | Fix the client, don't retry the same frame |
| 4401 | Not authenticated / token expired | `POST /auth/refresh`, then reconnect. If that fails, go to login |
| 4403 | Origin rejected / account disabled | Go to login |
| 4429 | Rate limited | Reconnect after the delay in the close reason |

### Groups (server-side)

| Group | Members |
|---|---|
| `user.{user_id}` | Every connection of that user |
| `server.{server_id}` | Connections currently viewing that server |
| `channel.{channel_id}` | Connections viewing that channel (permission-checked on subscribe) |
| `dm.{dm_id}` | Connections viewing that DM |

When permissions change (role edit, overwrite, kick), the server sends `server.removed` or `channel.deleted` to the affected users and removes their connections from the groups.
